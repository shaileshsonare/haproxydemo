HAProxy Conditional Routing

Architecture

System Overview

This document details the professional implementation of dynamic, state-aware load balancing using HAProxy Community Edition. The architecture utilizes Lua extensions to intercept requests and perform real-time lookups against external state providers.

Frontend

HAProxy 2.4+ acting as the entry gateway on port 8085.

Logic Layer

Lua 5.3 script using non-blocking TCP sockets for state checks.

Performance

Optimized Redis lookups using line-based RESP parsing.

Logic

Routing Logic Flow

The logic is designed for resilience. In the event of a state-provider failure, the system falls back to a stable default to prevent service disruption.

graph TD
    In([Client Request]) --> Action[Lua Routing Action]
    Action --> Conn{Provider Connected?}
    Conn -- No --> Default[Route to node2]
    Conn -- Yes --> Fetch[Fetch State Data]
    Fetch --> Parity{Condition Met?}
    Parity -- Yes --> Node1[Route to node1]
    Parity -- No --> Node2[Route to node2]
    Node1 --> Exit([Forward Request])

HTTP Implementation

HTTP-Based Routing

Routing based on an external HTTP API response.


core.register_action("do_routing", { "http-req" }, function(txn)
    local target = "node2" -- default fallback
    local tcp = core.tcp()
    
    if tcp:connect("127.0.0.1", 8081) then
        tcp:send("GET /count HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n")

        -- Parse logic...
        if count % 2 ~= 0 then
            target = "node1"
        else
            target = "node2"
        end
    end

    -- Health check logic
    local s_name = target == "node1" and "s1" or "s2"
    if not is_node_up(target, s_name) then
        core.Alert("ROUTING LOG: " .. target .. " is DOWN. Triggering fallback.")
        target = (target == "node1") and "node2" or "node1"
    else
        core.Info("ROUTING LOG: " .. target .. " is UP. Routing successfully.")
    end

    txn.set_var(txn, "txn.target_node", target)
end)
Resilience

Health Checks & Dynamic Fallback

The Lua script integrates directly with HAProxy's internal health state. If the target node is marked as DOWN, the request is automatically routed to a healthy alternative. Custom logs are emitted via core.Alert and core.Info.


local function is_node_up(backend_name, server_name)
    local b = core.backends[backend_name]
    if b and b.servers[server_name] then
        local status = b.servers[server_name]:get_stats()["status"]
        if status and (status == "UP" or status:sub(1, 2) == "UP") then
            return true
        end
    end
    return false
end

-- Fallback logic inside routing action:
if not is_node_up(target, s_name) then
    core.Alert("ROUTING LOG: " .. target .. " is DOWN. Triggering fallback.")
    target = (target == "node1") and "node2" or "node1"
else
    core.Info("ROUTING LOG: " .. target .. " is UP. Routing successfully.")
end
Observability

Custom Logging & Monitoring

To capture the custom core.Info and core.Alert logs generated by the Lua script, HAProxy must be configured to send its logs to the system's syslog. Once configured, you can monitor routing decisions and node failures in real-time.

1. Enable Logging in Configuration

Add the following directive to the global section of your haproxy.cfg:

global
    log /dev/log local0 debug

2. Viewing the Logs

On Ubuntu, the local0 facility is automatically routed to a dedicated HAProxy log file via rsyslog (/etc/rsyslog.d/49-haproxy.conf). Run this command to view the live logs:

tail -f /var/log/haproxy.log | grep "ROUTING LOG"

If the dedicated file isn't present, check the main system log: tail -f /var/log/syslog | grep "ROUTING LOG"

Redis Optimization

High-Performance Redis Routing

By using tcp:receive("*l"), we read specific RESP lines instead of waiting for a stream end. This optimization significantly reduces latency.


core.register_action("do_redis_routing", { "http-req" }, function(txn)
    local tcp = core.tcp()
    tcp:settimeout(0.1)
    tcp:connect("127.0.0.1", 6379)
    
    -- Redis GET oo_node1_users
    tcp:send("*2\r\n$3\r\nGET\r\n$14\r\noo_node1_users\r\n")

    -- Optimized: Read specific RESP lines
    local size_line = tcp:receive("*l")
    local value_line = tcp:receive("*l")
    tcp:close()

    local count = tonumber(value_line)
    if count and count > 10 then
        txn.set_var(txn, "txn.target_node", "node2")
    else
        txn.set_var(txn, "txn.target_node", "node1")
    end
end)
Config

HAProxy Configuration

Configuration of the frontend listener, backend node health checks (check), and a live stats dashboard on port 8404 for monitoring concurrent sessions.


frontend http
    bind *:8085
    
    # Execute the custom Lua action
    http-request lua.do_routing
    
    # Route based on the variable dynamically set by Lua
    use_backend %[var(txn.target_node)]

backend node1
    server s1 127.0.0.1:8082 check

backend node2
    server s2 127.0.0.1:8083 check

listen stats
    bind *:8404
    stats enable
    stats uri /stats
    stats refresh 5s
