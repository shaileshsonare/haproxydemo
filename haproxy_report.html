Load Balancing Analysis

Detailed analysis of load balancing configuration and traffic distribution

Executive Summary

This document provides a comprehensive breakdown of the HAProxy configuration deployed for the node_backend cluster. The primary objective was to implement a sequential overflow strategy using the first balancing algorithm.

Testing with 30 concurrent requests successfully validated that HAProxy respects the maxconn limits of each individual server, cascading traffic to subsequent nodes only when previous ones are saturated.

Deployment Commands

The following terminal commands were executed to initialize the backend node cluster with their respective port assignments and identities:

Node 1 Instance
PORT=8081 SERVER_NAME=node1 node app.js
# Output: node1 listening on 8081
Node 2 Instance
PORT=8082 SERVER_NAME=node2 node app.js
# Output: node2 listening on 8082
Node 3 Instance
PORT=8085 SERVER_NAME=node3 node app.js
# Output: node3 listening on 8085

Command Context:

  • The PORT variable ensures each instance binds to a unique local port (8081, 8082, 8085).
  • SERVER_NAME is injected into the application to provide identifiable HTTP responses.
  • Each node runs as a separate process to simulate a distributed environment.

Logging & Debugging

HAProxy logs provide essential visibility into request routing, connection timing, and backend health. To monitor logs in real-time, use the following command:

sudo tail -f /var/log/haproxy.log

How to read HAProxy HTTP logs:

  • 127.0.0.1:56826: Client IP and source port.
  • [08/May/2026:00:45:55.834]: Precise timestamp of the request.
  • stats stats/<STATS>: Frontend name and Backend/Server name.
  • 0/0/0/0/0: Timers (Tq/Tw/Tc/Tr/Tt) in milliseconds.
  • 200: HTTP status code returned to the client.
  • LR--: Termination state (L: local session, R: resource limit).

Global & Default Settings

global
    log /dev/log local0
    chroot /var/lib/haproxy
    stats socket /run/haproxy/admin.sock mode 660 level admin
    user haproxy
    group haproxy
    daemon

defaults
    log     global
    mode    http
    option  httplog
    timeout connect 5000
    timeout client  50000
    timeout server  50000
log
Configures Syslog destination. local0 is a standard facility for HAProxy logs.
chroot
Security feature that restricts the HAProxy process to a specific directory to minimize the impact of a potential breach.
stats socket
Creates a UNIX socket for runtime management. expose-fd listeners allows seamless reloads without dropping connections.
mode http
Enables Layer 7 load balancing, allowing HAProxy to inspect and manipulate HTTP headers and cookies.
timeout connect
Maximum time (5s) HAProxy will wait for a successful connection to a backend server.

Proxy Configuration Logic

frontend node_frontend
    bind *:8083
    default_backend node_backend

backend node_backend
    balance first
    cookie SERVERID insert indirect nocache
    option httpchk GET /health

    server node1 127.0.0.1:8081 maxconn 5 cookie s1 check
    server node2 127.0.0.1:8082 maxconn 10 cookie s2 check
    server node3 127.0.0.1:8085 maxconn 15 cookie s3 check
balance first
Algorithm that selects the first available server. This server is used until it reaches its maxconn limit, then traffic overflows to the next server.
cookie SERVERID
Enables session persistence. insert adds a cookie to the response; indirect removes it from the request before passing to the server.
option httpchk
Enables HTTP-based health checks. HAProxy sends a GET request to /health and expects a 2xx or 3xx response.
maxconn
Crucial parameter for the first algorithm. It defines the hard concurrency limit for each server node.
check
Enables active health monitoring for the specific server entry.
